KEM/DEM Hybrid Encryption — Cách mã hóa đúng trong thực tế
Combine asymmetric key encapsulation (KEM) + symmetric encryption (DEM) = IND-CCA2

KEM — Key Encapsulation
Asymmetric component
Input pk (Bob's public key)
Random r ← random bits
(k, c₁) ← Encap(pk)
k = symmetric key (32B)
c₁ = encapsulation (RSA/ECDH)
Examples: DHKEM(X25519), RSA-KEM,
ML-KEM (Kyber) — post-quantum

DEM — Data Encapsulation
Symmetric component
Input k (from KEM) + plaintext M
Nonce n ← random (96-bit)
(c₂, tag) ← AEAD(k, M, n)
c₂ = ciphertext of M
tag = authentication tag
Examples: AES-256-GCM,

Final Ciphertext
Sent to recipient
C = (c₁ ‖ c₂ ‖ tag ‖ n)
c₁ = KEM encapsulation
c₂ = encrypted message
tag = AEAD auth tag
n = nonce (often in c₂)
Key k is NEVER transmitted!
Only encapsulation c₁ is sent.

🛡️
Security Theorem (KEM/DEM): Nếu KEM đạt IND-CCA2 và DEM đạt IND-CCA2, thì Hybrid scheme đạt IND-CCA2. Đây là nền tảng của TLS 1.3 (ECDHE + AES-GCM), HPKE (RFC 9180), Signal Protocol, và hầu hết public-key encryption trong thực tế. Key k không bao giờ được truyền đi — chỉ có encapsulation c₁.
